# 模块：自动领券

## 1. 工具事实（先看清，再动手）

| 工具 | 参数 | 能做什么 | 不能做什么 |
|---|---|---|---|
| `available-coupons` | 无 | 列出麦麦省券，含 `已领取` / `可领取` 状态 | **不返回面额、有效期、积分价、费用字段**，无法据此证明"免费" |
| `auto-bind-coupons` | **无参数** | 一次领取当前全部可领券 | **没有按 couponId 挑选单张的参数**。任何"领取指定券"的参数都是编造 |
| `query-my-coupons` | `page`/`pageSize` | 领完后核对券包 | 不代表门店可用 |
| `query-store-coupons` | `storeCode`/`orderType`/`beType` | 领完后核对本店可用券 | — |

## 2. 两种触发

| 触发 | 行为 |
|---|---|
| 用户说「帮我领券」 | 先 `available-coupons` 展示可领清单 → 询问是否全部领取 → 授权后调 `auto-bind-coupons` |
| 用户在搭餐时开启「本次先自动领券」 | 落在已保存偏好范围内时**不再重复询问**，直接领，然后继续搭餐 |

## 3. 免费券偏好的保存

**位置**：项目记忆 `.workbuddy/memory/MEMORY.md（相对当前项目根目录）` 的「麦麦不白花偏好」小节。
**不要**写进技能目录（技能文件会被复制、分享，不放用户个性化数据）。

建议记录格式：

```markdown
## 麦麦不白花偏好
- 自动领取免费券：已启用
- 适用范围：仅到店自取；仅本人账户；单次搭餐流程内触发（不建定时任务）
- 启用时间：2026-10-23
```

规则：

- 只在用户**明确说过**"以后自动领"或"这个范围内不用再问"时才写偏好。
- 适用范围要能落地：就餐方式 / 城市 / 是否含外送 / 是否含团餐。范围外的领券请求仍要问。
- 用户说"取消自动领券"就删除该小节，不做"暂时关闭"的模糊态。

## 4. 免费与付费的边界

`auto-bind-coupons` 的工具说明是「自动领取麦麦省所有当前可用的麦当劳优惠券」，属于**麦麦省活动券路径**，与积分商城兑换（`mall-create-order`，会扣积分）是两条独立通道。

但必须诚实：**接口没有返回任何费用或积分字段**，所以"这些券一定免费"是推断，不是接口结论。因此：

- 正常情况按免费券处理，并在说明里写「按麦麦省活动券路径领取，不扣积分（接口未返回费用字段，此为路径推断）」。
- 一旦出现下列任一信号，**停止自动执行，转人工确认**：
  - `available-coupons` 文案里出现价格、积分、"付费"、"开通"、"协议"、"会员"字样；
  - 领券前被要求确认金额、支付方式或授权条款；
  - 用户没有明确授权，且偏好范围外。
- 绝不把"领取"说成"免费获得权益"，也不承诺领取后一定能用。

## 5. 标准流程

```
1. available-coupons           → 可领清单（状态=可领取）
2. 授权判断                     → 用户明确同意 / 命中已保存偏好
3. auto-bind-coupons            → 全量领取（一次调用）
4. query-my-coupons             → 刷新券包，核对新增
5. query-store-coupons          → 刷新本店可用券
6. 回到搭餐流程                  → 用刷新后的券生成候选
```

第 4、5 步不可省。领完不刷新，就会拿旧券包去试算，导致"明明领了却算不出优惠"。

## 6. 失败与超时

| 情况 | 处理 |
|---|---|
| `auto-bind-coupons` 返回失败 | 说明失败原因，**继续用现有券搭餐**，并在结果里标注「本次领券未成功，方案基于原有券」 |
| 超时 / 无响应 / 结果未知 | **先 `query-my-coupons` 查券包是否已经到账**，不重复调用 `auto-bind-coupons`（可能重复领取或触发风控） |
| 查完确认未到账 | 告知用户未成功，给出重试建议，但不擅自重试第二次 |
| 部分券领取成功 | 按实际到账的券刷新，说明"领到 N 张，M 张未领到" |

## 7. 禁止

- 不创建定时任务、不建后台轮询。自动领券只发生在**当前搭餐流程内**。
- 不为了凑券而扩大消费，不用"领了券不用就浪费"推动加购。
- 不批量反复调用 `auto-bind-coupons` 试探。
- 不在同一次搭餐里领券 → 试算 → 再领券 → 再试算地循环。
